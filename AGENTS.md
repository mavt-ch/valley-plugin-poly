# Study plugin

- Study is a growing set of study tools; the Menu plan is its first feature. Its left-sidebar panel `study.panel` is an Icon Rail entry (25 Nov: moved out of the Tab Rail on request; never declare `rail: "tab"`), icon `icon.svg` (fork and knife). Its page `study.page` is a fully custom main-workspace view (25 Nov: "not a link but completely custom"): dish cards with pictures, never an embedded or linked website. Both are built from `src/views.tsx`. Later features join these surfaces; they never move menu code into Valley core.
- The page's first bar keeps the host's reservations: `--plugin-navigation-offset` at the start (back/forward) and `--plugin-actions-offset` at the end (host menu).
- Menu data comes only from ETH's Cookpit service (`idapps.ethz.ch`, client id `ethz-wcms`, the one ETH's gastronomy page sends), the ZFV's food2050 pages (`app.food2050.ch`) and food2050's picture bucket (`storage.googleapis.com/dish-images-prod/`). `permissions.network.hosts` holds exactly these three. Never invent prices, opening hours or dishes a source does not supply. UZH prices and pictures come only from each dish's own page, read when its card is on screen.
- Host limits the backend must respect: `maxResponseBytes` at most 4 MiB (a larger ask is refused before any request; 25 Nov, every request failed with 6 MB). Cookpit answers 406 to `Accept: image/*` alone; picture requests accept `*/*` too. The tests' mock enforces both.
- ETH facilities are sorted by postcode, ETH's own rule (`ethZone`): Hönggerberg 8093, 8049, 8053 (`HOENGGERBERG_POSTCODES`), Oerlikon 8050, Basel 4xxx, Zentrum the rest; the tags ETH = Zentrum and Höngg = Hönggerberg, Oerlikon and Basel are not shown. Never a hard-coded facility list. UZH outlets come from the organisation page `universitat-zurich`; never a hard-coded outlet list.
- food2050 has no public API: `src/model.ts` reads the payload streamed in `self.__next_f.push([1,"…"])` scripts, takes the component properties that start with `{"outlet":` or `{"organisation":` and resolves the payload's `"$<id>:props:…"` references. When food2050 changes its pages, fix the parser and its fixtures in `tests/fixtures.ts`.
- Lunch and dinner are told apart by the meal's start time for ETH (from 15:00 is dinner) and by the category name or slug for UZH (`abend`, `dinner`, `evening`).
- Network requests run only in the backend (`src/backend/index.ts`), at most two at once, with a 30-minute memory cache for menus and 12 hours for the outlet lists and each outlet's page; `fresh: true` (Refresh) asks past it. The place list reads every UZH outlet's week as soon as the outlet list is known (25 Nov decision: complete counts and tags over lazy counts; 26 outlets, 2–3 requests each the first time, 1–2 once the outlet pages are cached) with `background: true`, which queues those reads behind the open page's reads and pictures.
- Menu plan design (25 Nov, on request): the sidebar is exactly three 38px rows, then the place list, never dishes: row 1 the `panel-header` with the title, Lunch | Dinner and the host `plugin-open-page` button (Music's corners icon); row 2 the campus tags ETH, Höngg, UZH drawn like To-Do's smart-list chips (icon tinted in the tag colour, label, count, filled when active; single choice like To-Do, saved in `campus`; a tag shows only while its campus has a place serving the meal that day); row 3 the day with the filter funnel. A place row shows name, menu count after filters, location and, only where the source gives opening hours, Open now/Closed with the hours. A click opens `study.page` with `instanceId` `place:<location id>` (⌘/middle click a new tab); without an instance the page shows the chosen campus. Day and meal are shared by both surfaces through the hidden `day` setting (a past day falls back to today). Filters are the `onlyVegetarian`, `onlyVegan`, `onlyGlutenFree` switches and the `price` select, edited from the funnel menu and Settings → Study alike. Gluten-free needs declared allergens without a gluten cereal (`gluten === false`); never call a dish without declared allergens gluten-free.
- Fixtures are invented (no staff names or real manager data from Cookpit's facility records).
- Keep the five catalogs (en, de, es, fr, zh-CN) on the same keys; a test pins them.
